# Реестр архитектурных рисков и мер контроля

Документ фиксирует риски целевой AQA-архитектуры и проверяемые меры контроля. Наличие меры в документации не означает, что она реализована: статус меняется на «Проверено» только после реализации и подтверждающего теста.

| ID | Риск | Последствие | Мера контроля | Проверка / критерий закрытия | Статус |
|---|---|---|---|---|---|
| R-01 | Нельзя однозначно связать тест с connectionId и PID | Lifecycle-логи нельзя надёжно приложить к конкретному тесту при параллельности | Отдельный control channel; AQA регистрирует заранее привязанный socket endpoint и clientSessionId; Bridge связывает endpoint с connectionId/PID | Параллельные сессии имеют уникальную цепочку runId/testId/clientSessionId/connectionId/PID; тесты на повторную/истёкшую регистрацию проходят | Спроектировано, реализация не начата |
| R-02 | Control channel становится дополнительной поверхностью атаки | Несанкционированный запуск процессов или утечка данных | Только внутренняя Docker network; порт не публикуется; ограниченные команды; валидация source IP, TTL, UUID, размера сообщений и частоты; без shell и секретов | Негативные тесты регистрации, port exposure и command allowlist | Спроектировано, реализация не начата |
| R-03 | Зависшие дочерние процессы и утечки ресурсов | Исчерпание CPU/RAM/PID, нестабильность CI | Таймауты запуска/остановки, лимит сессий, обработка EOF/reset, shutdown hook, force kill | Тесты отключения клиента, SIGTERM Bridge, start failure, session cap; после теста нет orphan process | Спроектировано, реализация не начата |
| R-04 | Повреждение MCP-потока диагностическими сообщениями | Ошибки JSON-RPC и ложные падения тестов | stdout дочернего процесса только для MCP; stderr отдельно; Bridge не меняет framing | Проверка байтовой прозрачности, stderr isolation и нескольких последовательных сообщений | Спроектировано, реализация не начата |
| R-05 | Автоматический повтор write-запроса создаёт дубликат | Дубли Jira issues, comments или Confluence pages | Нет общего retry для write; timeout после отправки = UNKNOWN_OUTCOME; сверка по маркеру/ID перед разрешённым повтором | Тест потери ответа после отправки create/comment/update и проверка отсутствия второго запроса | Спроектировано, реализация не начата |
| R-06 | Параллельные тесты используют одну сессию или конфликтуют данными | Смешение ответов, состояния lifecycle и данных | Одна сессия на тестовый класс; методы класса последовательны; уникальные runId/testId; worker count не выше Bridge capacity | Два и более класса параллельно; изоляция ответов, PID, diagnostics и маркеров | Спроектировано, реализация не начата |
| R-07 | Реестр теряется при аварии JVM/Jenkins | Нельзя идентифицировать оставшиеся Atlassian-объекты | JSONL append, немедленный flush/force, отдельная запись на объект и UNKNOWN_OUTCOME, архивирование в post/always | Искусственный сбой после создания; реестр и журналы присутствуют в артефактах | Спроектировано, реализация не начата |
| R-08 | Cleanup пропускается после ошибки pipeline | Остаются контейнеры, сети, тома и процессы | Независимые шаги cleanup в post/always; сбор диагностики до остановки Bridge | Принудительная ошибка на каждом pipeline stage; подтверждение очистки | Спроектировано, реализация не начата |
| R-09 | Утечка токенов через логи/Allure/исключения | Компрометация Atlassian tenant | Маскирование до attachment/log; запрет полного env dump; credentials только в Jenkins Credentials; минимальные права | Canary secrets в ответах/исключениях не обнаруживаются в логах и артефактах | Спроектировано, реализация не начата |
| R-10 | Контракт tools/list меняется, локальные ожидания устаревают | Неполные или ложноположительные контрактные тесты | Сверять все 13 инструментов и полные JSON Schema: type, required, properties, additionalProperties, bounds, annotations | Контрактный тест сравнивает полный набор схем с ожидаемой версией и показывает diff | Требует реализации |
| R-11 | Неопределённые внешние предусловия Jira/Confluence | Нестабильные integration tests | Выделенные project/space, минимальные права, известный workflow, валидные JQL/CQL, проверка доступности до набора | Environment preflight завершается до запуска интеграционных тестов | Требует настройки окружения |
| R-12 | Отсутствует API удаления тестовых объектов | Накопление тестовых сущностей | Не удалять через обход MCP; сохранять полный реестр; ручная/отдельная административная очистка с allowlist | Реестр содержит все созданные объекты и маркеры; cleanup не затрагивает чужие данные | Ограничение принято |

## Обязательные правила

1. Не объявлять архитектурную меру реализованной только потому, что она описана в документации.
2. Любой риск, влияющий на целостность MCP-потока, корреляцию, повтор write-запроса, секреты или cleanup, должен иметь отдельный тест.
3. При неизвестном исходе операции записи запрещено автоматически повторять запрос.
4. Process lifecycle считается проверенным только при наличии точной корреляции, а не по временному окну или PID без связи с тестом.
5. Все созданные Atlassian-объекты должны попадать в устойчивый реестр; автоматическое удаление через несуществующий MCP-инструмент запрещено.
