# Каталог тест-кейсов

Каталог описывает black-box проверки Atlassian MCP Light через публичный MCP/JSON-RPC контракт и штатный STDIO транспорт. AQA самостоятельно запускает тестовый экземпляр сервера как локальный Java-процесс или как Docker-контейнер через Docker CLI. Bridge и TCP-соединение в архитектуре не используются.

## Общие правила

- ID стабильны и не переиспользуются: MCP-xxx, JIRA-xxx, CONF-xxx, PROC-xxx, DATA-xxx, REL-xxx.
- Приоритеты: P0 — критичный для базовой работоспособности; P1 — важная функциональность; P2 — дополнительный негативный/граничный сценарий.
- Типы: Protocol, Process, Integration, Negative, E2E.
- Все write-сценарии используют выделенное тестовое окружение.
- Фактические схемы, версии и ошибки сверяются с [mcp-contract.md](mcp-contract.md).
- Одна MCP-сессия использует один процесс; один процесс не разделяется между независимыми тестовыми клиентами.

## 6. Test Data Management

- Каждый write-сценарий использует уникальный run/test marker.
- До отправки write-запроса сохраняется WRITE_INTENT.
- Подтверждённый результат сохраняется как WRITE_CONFIRMED.
- Однозначный отказ без побочного эффекта сохраняется как WRITE_REJECTED.
- Потеря ответа после возможной отправки запроса фиксируется как UNKNOWN_OUTCOME.
- Автоматический retry write-операций запрещён.
- Реестр созданных Jira issues и Confluence pages сохраняется как артефакт Jenkins.
- В текущем MCP-контракте нет инструментов удаления; автоматическая очистка через прямой Atlassian REST API из AQA не выполняется.
