# Реестр архитектурных рисков и мер контроля

Документ фиксирует риски целевой AQA-архитектуры и меры контроля. Наличие меры в документации не означает, что она реализована: статус меняется на «Проверено» только после реализации и подтверждающего теста.

| ID | Риск | Последствие | Мера контроля | Проверка / критерий закрытия | Статус |
|---|---|---|---|---|---|
| R-01 | Тестируемый процесс не запускается или завершается сразу | MCP Client не может начать протокольный обмен | Проверка состояния процесса и отдельный MCP readiness handshake | Ошибка запуска и startup timeout дают контролируемую диагностику; ProcessBuilder.start() не считается readiness | Спроектировано, реализация не начата |
| R-02 | STDOUT содержит диагностические сообщения | Нарушается JSONL framing и парсинг MCP-ответов | STDOUT зарезервирован под MCP; STDERR читается отдельным collector | Проверить отсутствие посторонних строк в STDOUT и независимое чтение STDERR | Спроектировано, реализация не начата |
| R-03 | STDERR pipe не читается и заполняется | Процесс блокируется на записи логов | Независимый асинхронный STDERR collector | Длительный/большой stderr output не блокирует MCP-обмен и завершение процесса | Спроектировано, реализация не начата |
| R-04 | Процесс остаётся работать после завершения теста | Утечка процессов и ресурсов CI-агента | JUnit lifecycle cleanup, graceful shutdown, timeout и force termination | Проверки cleanup после успеха, assertion failure, exception и timeout; отсутствие orphan process | Спроектировано, реализация не начата |
| R-05 | Завершение Docker CLI оставляет контейнер | Orphan container продолжает работать после теста | Уникальный container ID/name, docker stop и при необходимости docker rm -f; --rm как дополнительная мера | Прервать Docker CLI и проверить остановку/удаление только контейнера текущего run | Спроектировано, реализация не начата |
| R-06 | Два теста используют один STDIO-поток одновременно | Смешение запросов/ответов и повреждение состояния MCP | Один процесс на одну MCP-сессию; один reader loop; методы класса выполняются последовательно; классы запускаются параллельно | Параллельные независимые процессы не смешивают ответы и потоки | Реализовано, ожидает подтверждающего теста |
| R-07 | Не воспроизводится версия тестируемого сервера | Нельзя установить, какой код проверялся | Checkout основного проекта по выбранному ref; фиксация полного commit SHA в отчёте | В каждом Jenkins run опубликован commit SHA; повторный запуск возможен на той же ревизии | Спроектировано, реализация не начата |
| R-08 | Автоматический повтор write-запроса создаёт дубликат или повторное изменение | Дубли Jira issues/comments/Confluence pages или повторный transition | WRITE_INTENT до отправки; запрет общего retry; UNKNOWN_OUTCOME при потере ответа; сверка перед повторным create | Потеря ответа не приводит к автоматической повторной отправке; registry сохраняет неопределённый исход | Спроектировано, реализация не начата |
| R-09 | Реестр теряется при аварии JVM/Jenkins | Нельзя идентифицировать созданные/неопределённые объекты | Append-only JSONL registry, синхронная запись intent до отправки, архивирование в post/always | Проверить recovery незавершённого intent и доступное архивирование при сбоях | Спроектировано, реализация не начата |
| R-10 | Cleanup не выполняется после потери Jenkins agent/host | Остаются контейнеры и другие ресурсы | post/always при доступном agent; отдельная host-level политика для orphan Docker resources | Явно проверить границы гарантии: Pipeline не может очистить ресурсы после потери собственного host | Спроектировано, реализация не начата |
| R-11 | Утечка Jira/Confluence credentials через логи/Allure | Компрометация Atlassian tenant | Jenkins Credentials, передача только тестируемому серверу, маскирование и запрет полного env dump | Canary secrets отсутствуют в Jenkins console, STDERR, STDOUT и Allure attachments | Спроектировано, реализация не начата |
| R-12 | MCP tools/list меняется, локальные ожидания устаревают | Ложноположительные/неполные контрактные проверки | Сравнение имён, полных JSON Schema и annotations с эталонным MCP contract test data | Контрактный тест выявляет diff схем и annotations | Реализовано, ожидает запуска на актуальном сервере |
| R-13 | Неопределённые предусловия Jira/Confluence | Нестабильные integration tests | Выделенные project/space, минимальные права, известный workflow, environment preflight | Preflight завершается до integration-набора и сообщает недостающие настройки без раскрытия секретов | Требует настройки окружения |
| R-14 | Отсутствует MCP API удаления тестовых объектов | Накопление Jira issues и Confluence pages | Устойчивый реестр и последующая административная очистка; запрет обхода MCP через REST в AQA | Все созданные объекты и markers присутствуют в registry; автоматическое удаление не затрагивает чужие данные | Ограничение принято |
| R-15 | Параллельные Jenkins runs используют общие Docker resources | Один прогон может остановить/удалить контейнер другого | Базовый AQA_RUN_ID и уникальный суффикс имени каждого контейнера | Два Pipeline на одном Docker host имеют независимые ресурсы и cleanup | Уникальные имена реализованы, параллельные Jenkins runs не проверены |

## Обязательные правила

1. Не объявлять архитектурную меру реализованной только потому, что она описана.
2. Любой риск, влияющий на целостность MCP-потока, cleanup, повтор write-запроса или секреты, должен иметь отдельный тест.
3. При неизвестном исходе write-операции запрещено автоматически повторять запрос.
4. Жизненный цикл процесса считается проверенным только после подтверждения завершения процесса/контейнера, а не только закрытия локального Process handle.
5. Credentials передаются только тестируемому серверу и не попадают в AQA logs/Allure.
6. Jenkins post/always гарантирует cleanup только пока доступны agent, workspace и Docker Engine.
7. Локальный и Docker режимы используют один MCP Client; отдельный сетевой транспорт не вводится.
8. Все созданные Atlassian-объекты должны попадать в устойчивый реестр; автоматическое удаление через отсутствующий MCP-инструмент запрещено.
